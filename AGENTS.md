# AGENTS.md

Operating contract for this repo. README.md has the narrative.

## Vocabulary
- **Kyvvu policy / manifest**: `demo-manifest.yaml`; behavioural rule evaluated in-process per declared step.
- **sandbox policy**: `sandbox.json`; host restrictions applied once by `shadictl`, enforced by the kernel.

## Files
| path | role | edit? |
|---|---|---|
| `agent.py` | agent; tools `write_code` (step.resource POST), `run_code` (step.exec); modes `benign`/`tamper`, flag `--no-gate` | yes |
| `demo-manifest.yaml` | one rule: `step_requires_gate` on `step.exec` | keep the exec rule |
| `sandbox.json` | template with `__AGENT_DIR__` / `__OUT_DIR__`; `run.sh setup` renders it into `my-agent/` | template only |
| `run.sh` | `setup`, `demo`, `1`, `2`, `3a`, `3b`, `examples`, `clean`; directories are relative to the script | yes |
| `examples/` | three further Kyvvu policies, the custom rule `input_equals_history_output` (`scoped_rule.py`) and `run_examples.py`, which checks every outcome and exits 1 on a difference. Independent of `agent.py`, `demo-manifest.yaml` and SHADI | yes; keep `run_examples.py` in step with the policies |
| `my-agent/`, `agent-out/` | generated by `setup`; git-tracked (`my-agent`) so `git status` is the tamper check | never commit |

## Invariants
1. `shadictl` runs with cwd `agent-out/`. From `my-agent/` the profile makes it writable and 3b proves nothing.
2. `sandbox.json`: `read` = `my-agent` (contains `.venv`) plus the interpreter's base installation (added by `setup`), `write` = `agent-out` only, `net_block: true`.
3. Manifest passed via `KyvvuSettings(policy_file=..., explicit_fields={"policy_file", ...})`; env `KV_POLICY_FILE` is not equivalent when `KV_API_KEY` is set. `run.sh` unsets `KV_API_KEY`.
4. Gate recorded as `kv.add_step(ActionKind.step_gate, "human_approval", properties={"kind": "human"}, output={"decision": "pass"})`; a gate without `output.decision == "pass"` (no decision, or `deny`) does not satisfy the rule. The manifest names its target as `target_kinds`.
5. Trace goes to `agent-out/kyvvu-trace.jsonl` (`log_location` = file path).

## Expected outcomes
| run | Kyvvu on `run_code` | effect |
|---|---|---|
| 1 | permitted | `agent.py` modified; `run.sh` restores it |
| 2 | refused ("Code execution requires a preceding gate") | exit 1, no execution |
| 3a | permitted | `agent-out/result.txt` = `42` |
| 3b | permitted | `PermissionError` in the child on `agent.py`; `git status` clean |

## Environment facts (verified 2026-09-20; all four runs re-verified 2026-10-09)
- 2026-09-20: shadictl 0.1.10, Linux 6.18, Landlock ABI 7; kyvvu 0.20.0, kyvvu-engine 0.11.0, Python 3.12.
- 2026-10-09: shadictl 0.1.11; kyvvu 0.22.1, kyvvu-engine 0.12.0. Linux 6.18 / Python 3.13 and macOS Apple Silicon (Seatbelt) / Python 3.14. Same outcomes.
- 2026-10-13: shadictl 0.2.0; kyvvu 0.22.1, kyvvu-engine 0.12.0. Linux 6.18 / Python 3.13. Same outcomes.
- 2026-11-16: ported to kyvvu 1.1.0 (engine 1.1.0): `ActionKind` for `StepType`, `target_kinds` for `target_step_types`, gate decision in `output`. shadictl 0.2.0, Linux 7.0 (Landlock, in a clean `python:3.12` container). Same outcomes.
- 2026-11-18: kyvvu 1.1.0 (engine 1.1.0), shadictl 0.2.0, macOS Apple Silicon (Seatbelt) / Python 3.14, fresh clone: the four scenarios and all 13 example outcomes as expected. Under SHADI on macOS the agent's log timestamps are in UTC.
- 2026-11-18: `examples/` added and run on kyvvu 1.1.0 (engine 1.1.0), Linux 6.18 / Python 3.13: all 13 outcomes as expected. The custom rule reads a tool's return value at `output.result`, because the `@kv.step` decorator records a return value under `result`.
- `run.sh` pins `kyvvu==1.1.0` (`KYVVU_VERSION` overrides). SDK 1.1.0 requires `kyvvu-engine>=1.0.0,<2.0.0`, and the engine stays compatible within a major version, so the engine needs no separate pin. Bump only after re-running all four scenarios. Before 1.x the engine had to be pinned too: SDK 0.22.1 admitted engine 0.13.0, which it could not import.
- SHADI's `install.sh` supports Linux only (`error: this installer only supports Linux hosts` on macOS, seen 2026-11-18). On macOS `setup` installs `shadictl` with Homebrew (`brew tap agntcy/shadi https://github.com/agntcy/shadi && brew install agntcy/shadi/shadictl`), which gives the formula's version (0.2.0 on 2026-11-18), not `SHADI_VERSION`.
- `run.sh` pins `SHADI_VERSION=0.2.0` for the Linux installer (override with the variable). Unpinned, the installer resolves "latest" across all AGNTCY releases and, since `agntcy-agentbridge-cli-v0.3.0`, aborts: `latest release tag agntcy-agentbridge-cli-v0.3.0 does not match agntcy-shadi-cli-v<version>`. The installer places `shadictl` in `/usr/local/bin` or `~/.local/bin`.
- Landlock is inherited by all descendants; `subprocess.run` needs no configuration.
- Under SHADI the venv's interpreter must be readable. `setup` renders `my-agent/sandbox.json` with the venv's Python and adds its base installation (`sys.base_prefix`, and its resolved path) to `read`, so any interpreter works: system, pyenv, uv, Homebrew, `actions/setup-python`. Without it, an interpreter outside SHADI's default system locations fails in 3a and 3b with `spawn failed: Permission denied`. `write` stays `agent-out` only.
- Network facts below were checked on shadictl 0.2.0, Linux. The 0.1.11 findings (agntcy/shadi #340, #430, #431) are fixed in 0.2.0.
- `net_allow` with `shadictl --watch-policy` (loopback proxy, HTTP and SOCKS5): the allowed host is reachable and any other host gets `403` from the proxy. An entry `host:port` allows that port only: with `example.com:443`, `http://example.com` is refused.
- Under `--watch-policy`, `curl`, `urllib` and `requests` reach an allowed host. `httpx` raises an ImportError about `socksio`, because `ALL_PROXY` is set to `socks5h://`; install `httpx[socks]` or unset `ALL_PROXY` in the child.
- `net_allow` without `--watch-policy`: an entry needs a port (`example.com` alone is refused at launch with a message). Enforcement is then per port, so `example.com:443` leaves every host on port 443 reachable.
- `block_command` applies to the top-level launched command only.
- Landlock does not govern `utime`/`chmod`; test writes with `open(..., "a")`.
- Kyvvu's full bundled baseline needs declared tools, which SDK 0.20.0 only accepts via `register_agent()` + API key. Keep the single-rule manifest.
